## FEATURE: END DEBATE

### How it works
- Motion passes → endDebateInDB sets ended_at + expires_at (**now + `ENDED_KEEP_HOURS`, 24 hours**, database clock; it was 1 hour until 7 Oct 2026) + phase='adjourned', freezes the caucus total and pauses the speaker clock like a suspension. **Idempotent** (audit V-8): conditional on `ended_at is null`, so a second device never rewrites `ended_at` or restarts the deletion countdown; resolves true when the committee has ended (now or earlier), false only when the write failed, and the caller rolls back. MotionsModal's optimistic mirror and the chair page's organiser-broadcast path read `ENDED_KEEP_HOURS` from `src/lib/roomRetention.ts` too, so the three cannot drift.
- All devices detect via realtime → setSessionEnded(true)
- Both chairs and delegates see: two-tab overlay (🏁 End View + 👁 Session View)
- **Download the record (23 Sep 2026).** The chair's End View leads with a big "Download the record" button (`DownloadRecordButton` on the chair page, `session_record_*`), and the scoreboard header's old Export CSV is now "Download record" (`sb_export_record`). Both call `downloadSessionRecord(committee, feedback?)` (`src/lib/sessionRecordExport.ts`, `xlsx` loaded lazily), which writes `<CODE> <committee> record.xlsx` with six sheets: History (every logged event in time order: segment, type, delegation, duration, motion, outcome, points, chair comments), Scores (headline, objective, quality, counts, points per source, ratings), Per motion (proposer, description, times, outcome, speeches, points by delegation = the motion's own ledger rows plus the speeches of the segment it opened), Speeches, Attendance (`delegate_status_history` through `sessionClient`, else the current statuses) and Documents (sponsors, signatories, status, approval, vote result and counts from `vote_state`). All numbers come from `buildSessionScoreboardRows` / `buildSessionHistory`, so the file matches the screen. English headers, like the CSV. Writes nothing.
- End View shows: "This committee has ended" + `session_kept_until` (standalone rooms only; a conference room is never deleted, so it shows nothing) + a countdown computed from `expires_at`, not a fixed promise — `Math.max(1, ceil(ms/1h))` (chair and delegate pages) rendered through `session_hours_until_delete`. With the 24-hour window it opens on "24 hours until committee is deleted". **Restart the session** sits between the record download and that line while the room is still restartable (see Rules below)
- Session View: full session visible but READ-ONLY
- pg_cron job runs hourly, deletes committees where expires_at < NOW() — so with the 24-hour window an ended STANDALONE committee is really gone 24–25 hours after the gavel, which is what makes the restart window below a promise the database keeps. It deletes ONLY the `committees` rows (23 Sep 2026): every child FK is ON DELETE CASCADE and the cascades run after the BEFORE DELETE trigger `archive_committee_on_delete`, so the archive counts real children. It used to delete the children first, which is why `committee_analytics` recorded zero delegates, messages and motions for every expired room. `archive_committee_before_delete()` now also stores `speeches`, `motions_passed` (from the ledger), `max_phase_reached` (`pre-session` < `speakers-list` < `caucus` < `voting`, from the log, the phase and any stored vote_state), `seat_claims`, `end_reason` (`ended` | `suspended_timeout` | `expired`); `total_messages` counts chat rows only (not the `__log__` ledger), `total_motions` = motions still on the floor + every `motion-raised` on the ledger, and the archived `settings` never keep `chairJoinSuffix`. The trigger swallows its own errors (a warning), so analytics can never block a delete. **`delete_expired_committees()` skips `session_origin = 'conference'` entirely**: a conference room is never auto-expired, however long ago it ended
- Whenever a CONFERENCE committee is deleted (by whatever route), its chat attachments in storage go with it and its submitted documents stay. See FEATURE: CHAT → Attachments and GIFs

### Read-only rules (when sessionEnded=true)
- Hide: Roll Call / Motions / Documents tabs and the Chat icon (top bar)
- Hide: Add speaker input, timer start/next buttons, time controls
- Hide: delegate status change buttons, request to speak, document submit
- Show: all lists, timer display, documents view, stats, chat (view only — compose disabled)
- ChatPanel readOnly={true} prop disables compose input

### Rules
- **An end can be undone for 24 hours (owner, 7 Oct 2026: "make a change that when someone ends debate, going onto the same session within 24 hours, it still allows them back in to restart it. This happened in some committees where they accidentally ended it. Make sure the room lives at least until the conference ends + 1 day").** `endedAt` is NO LONGER permanent, and nothing may be written on the assumption that it is.
  - The two numbers are `ENDED_KEEP_HOURS` and `REOPEN_WINDOW_HOURS` in `src/lib/roomRetention.ts`, both 24, deliberately the same: a room must still EXIST to be reopened, and `endDebate` used to keep a standalone room one hour, so the cron deleted an accidentally ended room before anyone could get back to it. Changing the reopen window without the keep window would be a promise the database breaks. `canReopenEndedRoom(committee, nowMs)` is the one test and `nowMs` is ALWAYS the database clock (`serverNow()`, RULE 6b).
  - A **conference** room is never auto-expired at all (`delete_expired_committees()` filters `session_origin <> 'conference'`), so it always outlives its conference by any margin and the owner's "at least until the conference ends + 1 day" is satisfied by that alone; `expires_at` on such a room is inert. Nothing writes `expires_at` from a conference's dates.
  - **Where it is**: "Restart the session" (`session_restart_btn`) on the chair's End View, between Download the record and the kept-until line, drawn only while `canReopenEndedRoom` holds (re-derived once a minute beside `hoursRemaining`, never per second) and never as a dead button past the window. It asks first in an inline card (`session_restart_ask`, `session_restart_yes` / `session_restart_no`): an accidental restart is the same accident again.
  - **Offered to ANY chair device, Commenter included.** The join page forces every chair on an ended room down the Commenter path, so the person who has to undo the accident arrives view-only; `isViewOnly` is never a permission (rule 15) and the chair suffix is the real credential. After the reopen lands, that device takes the gavel when the gavel is free or already names this chair (one attempt, silent on failure: "Take the gavel" is still in the top bar).
  - **What it writes**: `reopenEndedSession(committeeId, code, chairSuffix?)` (`committeeService.ts`, right after `endDebate`) sets `{ ended_at: null, expires_at: null, suspended_at: null, resuming_chair: null, phase: 'pre-session' }` in ONE conditional statement (`.not('ended_at','is',null).gte('ended_at', serverNow() - 24 h)`), row-counted, re-reading the row on zero rows, through `runWrite(lifecycleKey(id), …, { retry: true, rerunnable: false })`. **`rerunnable: false` is load-bearing**, like `suspendDebate` and `endDebate` (S3): the three attempts are safe to repeat, but PARKING is not. A parked write keeps its promise pending, so the caller's rollback would never run and the chair would sit looking at a room the database still has ended, with no failure shown and a reopen that could land minutes later out of context. Failing after the attempts is the honest answer. One statement because the phase can never be written without the end being lifted: `setPhase` is conditional on `ended_at is null`, which is exactly what this undoes. Optimistic first and then checked (RULE 5): on false BOTH the row fields and the two overlay flags go back and `session_restart_failed` is shown (never a raw error).
  - **It lands in `pre-session`**, exactly where a resumed suspension lands, so the dais takes roll again and Begin Session restores a paused caucus through `beginSessionAfterRollCall` (C-1): a reopened room can never come back with a running clock or a phantom speaker. `suspended_at` and `resuming_chair` go with it, so a room suspended and then ended reopens clean rather than into a half-held resume latch.
  - **The un-end propagates, but an END always wins over a stale read.** An end crosses in both `apply('row')` branches as it always did. An UN-END is deliberately asymmetric, because our own End Debate bumps `localWriteSeq` before its write is issued: the STALE branch never carries one (stale means a click on this device landed after the fetch started, and ending the session is exactly such a click), and the in-window / held branch carries one only while `rowHeld` is false, i.e. no lifecycle write of ours is in flight. Without those two guards a fetch issued just before End Debate answers `ended_at: null`, which as a plain "transition" cleared the stamp and flashed the live room back at the chair who had just ended the session until the 250 ms retry. A real un-end still reaches a co-chair in about a second (measured 1.4 s including the test's own polling), because a device that wrote nothing is neither stale nor held. The overlay flags themselves are cleared by the `prevLifecycleRef` effect, never from the event. The delegate page's lifecycle mirror is no longer set-only and keeps `wasEverEnded` beside `wasEverSuspended`, so a restarted room shows the WAITING screen, not a live board nobody is running. The voting page's entry effect stands down while the phase is `pre-session`, so it can never write `phase = 'voting'` over the restart.
  - **Honest limits, both verified on 7 Oct 2026.** (1) The window is a PostgREST filter built from this device's CORRECTED clock, not a server-side `now()`, because a server check would mean a new database function (the owner's to apply); a device whose clock is wrong AND whose `server_now()` measurement failed could reopen an older room. (2) The reopen writes only the five lifecycle fields and never touches `current_speaker`, so it inherits whatever End Debate left. In the real flow that is nothing (End Debate pauses the clock and MotionsModal clears the floor, verified), but if a floor clear ever failed on the network while the end landed, the room would come back with a seated speaker; the `turnKey` dedupe still stops that speech being logged twice. (3) A CONFERENCE room is capped at 24 h too even though it is never deleted, so there the limit is a product choice rather than a database promise.
  - **The rejoin blob survives the end.** `gavelling-rejoin` is kept while the room is still restartable (it is the one thing that brings the chair back) and forgotten only once the window has passed; `REJOIN_MAX_AGE_MS` in `LiveRoomsGate` reads `REOPEN_WINDOW_HOURS`, and `checkStandaloneRoom` offers an ended room inside the window with `ended: true`, whose card says what pressing it does (`srp_rejoin_ended_note`). `'gone'` still means deleted, or ended too long ago.
- Chair/delegate join page shows "view only" banner when endedAt is set
- Join still allowed for both roles when ended
- 'adjourned' phase with NO endedAt = suspended state (shows Resume button)
- 'adjourned' phase WITH endedAt = ended state (shows "Session Closed", plus Restart the session inside the 24 h window)
