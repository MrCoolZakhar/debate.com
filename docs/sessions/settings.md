## FEATURE: SETTINGS

### WRITE side — KEY-LEVEL PATCHES ONLY (migration `session_settings_patch_and_persisted_votes`, 14 Sep 2026)
- Every write to `committees.settings` sends ONLY the changed keys through a SECURITY INVOKER RPC that merges in one statement (`settings = coalesce(settings,'{}') || patch`). There is no read first, so there is no read-modify-write race between chairs (D-1) and no failed read that can wipe the blob (D-2). RLS still applies: `sess_chair_update` checks the `x-chair-suffix` header sent by `sessionClient(code, suffix)`.
- `patchCommitteeSettings(committeeId, patch, code, suffix)` → `patch_committee_settings`. Returns `true` only when a row was updated (an RLS refusal is a zero-row result, not an error). With `OFFLINE_RESILIENCE` on (Oct 2026) it runs as a retried, parkable `runWrite` with per-key ownership (see Offline resilience), so `false` means a real refusal only, never a dropped request. It **raises** on `chairJoinSuffix`. `saveCommitteeSettings` is now a thin wrapper that drops `chairJoinSuffix`, `separateChairCode`, `headChair`, `headChairDevice`, `agendaTopicIndex`, `votingReturnPhase` and `gslHeldFloors` from the patch and returns the same boolean.
- `SettingsPanel`'s `upd` updates the store instantly and debounces (400 ms) a patch of the keys changed since the last flush. It **never** posts `getSettings(code)`. A refused write shows `settings_write_failed`. `updScoring` → `updateCommitteeScoringInDB` patches `{ scoring }` (the scoring object is still one value, so two chairs editing different score sources in the same second resolve last-write-wins).
- The voting page's `applyRule` patches `{ [key]: value }` and is a no-op for a Commenter.
- Keys with their own writer: `chairJoinSuffix` → `updateCommitteeChairSuffixInDB` → `set_committee_chair_suffix` (four digits; RLS means the caller must hold the CURRENT code, so a committee with no code in the DB still cannot be given one from the client, exactly as before). `headChair` + `headChairDevice` → `updateCommitteeHeadChairInDB` (one patch, then appends the holder to `chair_names`). `agendaTopicIndex` + `committees.topic` → `updateCommitteeAgendaInDB` → `set_committee_agenda` (one statement). `votingReturnPhase` → `set_committee_voting_phase` only.
- `addChairName` → `add_committee_chair_name`: atomic `array_append` guarded by "not already present" in the same statement, so two chairs joining at once both land. The name is trimmed first (and `updateCommitteeHeadChairInDB` trims the gavel name), so " Alice" and "Alice" are one chair.
- `rowToCommittee` surfaces the blob as `committee.dbSettings` plus the convenience fields `dbChairJoinSuffix`, `dbHeadChair`, `dbHeadChairDevice`, `dbSeparateChairCode`, `dbScoring`.

- `NON_HYDRATED_SETTING_KEYS` / `stripNonHydratedSettings` in `src/lib/settingsStore.ts` is the ONE list of keys that never enter the store: `chairJoinSuffix`, `separateChairCode`, `headChair`, `headChairDevice`, `agendaTopicIndex`, `votingReturnPhase`, `gslHeldFloors` (18 Oct 2026: interrupted GSL speakers held for their resume, written only by `src/lib/gslFloorReturn.ts` as key-level patches and read only from the row as `committee.dbGslHeldFloors`, parsed defensively by `parseGslHeldFloors`). Both the chair and voting loaders hydrate through it (V5); never strip an inline copy again.
- `useSettingsSync` (`src/lib/useSettingsSync.tsx`) keys an effect on a stable serialisation of the stripped blob (never on object identity, which changes on every refetch), diffs it against the previous one and hydrates ONLY the changed keys, so a key this chair edited and has not flushed yet is never flashed back by an unrelated refetch. A changed value that matches one THIS device flushed in the last 15 s (`src/lib/settingsEcho.ts`, recorded by `patchCommitteeSettings`) is this device's own echo and is skipped: no flicker back to an older value, no notice (V3). Any other changed value that differs from this device's store came from another chair and a 4.5 s `settings_updated_by_other_chair` notice is shown. It never writes the DB and is not inside the realtime callback. It only sees what `committee.dbSettings` already carries, so a change that arrives inside the chair page's 3 s debounce lands when the session sync fetches the row again as the window closes (R-3).
- **ALWAYS** read a setting on a non-chair surface with the pure-function-of-the-committee-row pattern: `getCommitteeFlags(committee)` / `sponsorLabel(committee, fallback)` in `src/lib/committeeFlags.ts`, `getScoringConfig(committee)` in `src/lib/scoring.ts:31`, `docName(committee, ...)` in `src/lib/docNames.ts`. These read `committee.dbSettings` / `committee.dbScoring` and never touch localStorage.
- **NEVER** call `getSettings(code)` on the delegate or advisor pages — the store is empty there and you silently get `DEFAULT_SETTINGS`.
- Residual instance, **dead code, not a live bug**: `delegate/[code]/page.tsx:930` calls `getSettings(committee.code)` and `:939` builds `enabledMotionTypes` from it — but `enabledMotionTypes` is referenced nowhere (verified: the identifier appears only at its own declaration). Left over from the removed delegate Motions tab. Delete both; that removes the delegate page's last `useSettingsStore` dependency, which is the correct end state. Do **not** "fix" it by rewiring it to `dbSettings` — there is no consumer to fix.

### Chair code system
- `chairJoinSuffix`: 4-digit string, generated at committee creation (`committeeService.ts:100`) and stored in `committees.settings`.
- `SettingsPanel.tsx:415-425` regenerates it **only** when the store copy is `''`, and otherwise re-syncs the existing one to the DB via `updateCommitteeChairSuffixInDB`.
- Full chair code format: `{code}-{suffix}` e.g. "UNSC2026-4821".
- **People see it as the "chair password" (13 Oct 2026):** the 4 digits alone (the organiser chip on the committees page shows and copies only the suffix; the join page field is "Chair password", placeholder "4-digit chair password", compared trimmed against `dbChairJoinSuffix`, which `rowToCommittee` now always maps to a string). Typing the full form still works. In a room with no chair names the join page derives its name mode as `new` (`effectiveNameMode`), so Join turns on.
- Join page validates against `foundCommittee.dbChairJoinSuffix` (from DB), falling back to localStorage only if the DB value is missing (`join/page.tsx:281`).
- Landing page: if code contains dash with 4-char suffix → auto-routes to chair tab.
- Chair code NOT shown in the top bar (only the 6-char session code is, as a copy button) — only visible in Settings → Access panel.
- The suffix is also the **only** write credential: `sessionClient(code, suffix)` sends it as the `x-chair-suffix` header and RLS checks it (see FEATURE: CHAIR ROLES).
- `separateChairCode` is **not** a `CommitteeSettings` field. It is written literally as `true` at create time (`committeeService.ts:108`), surfaced as `dbSeparateChairCode`, read by no code, and explicitly stripped on hydrate. Do not build on it.

### Settings → People (15 Sep 2026, migration `session_participants_and_chair_kick`)
- **This reverses "No chair can free a seat".** Peter's instruction on 15 Sep 2026: chairs can see everyone connected and remove them, and that lives in Settings → People. Wrappers: `src/lib/sessionParticipants.ts`.
- `session_participants(p_code)` SECURITY DEFINER, `search_path = public, pg_temp`, anon + authenticated, gated on `is_session_chair` (the `x-chair-suffix` header through `sessionClient`). Returns chair names, the gavel holder, live seat claims (country, `account` or `device`, claimed / last seen, `active` = seen in the last 2 min; claims past the 65-minute expiry are omitted), signed-in chair devices from `chair_device_claims` (`active` = 90 s), the conference's assigned chairs by `profiles.display_name` (conference sessions only), and seats kicked in the last 10 minutes. Each seat claim carries `reserved` (the holder is that reserved seat's allocated conference account; a boolean, no identity). Never an email, a user id, a holder key or a device hash; `key` is `left(sha256(committee_id || ':' || user_id), 16)`, opaque and salted per committee so one account's key cannot be linked across committees (migration `session_people_review_fixes`; `release_chair_device_claim` matches the same salted key). The tab polls it every 15 s while visible.
- `kick_delegate_seat(p_code, p_country)`, chair-gated: under the seat advisory lock only (the LAST lock in `claim_delegate_seat`'s order, so no deadlock), deletes every claim on that seat EXCEPT the allocated account of a reserved conference seat (`seat_claim_holder_is_allocated`, owner-only helper), and writes one `delegate_seat_kicks` row per removed holder (`committee_id` cascade, `country`, `holder_key`, `device_hash`, `kicked_at`; RLS on, no policies, no table grants; rows older than a day are pruned on the next kick). The client then broadcasts `kicked` `{c: seatKey(country)}` on Realtime topic `seat-kick-<committeeId>`.
- **Reserved seats are protected (review fix).** The chair suffix is anon-readable, so without this anyone with the session code could keep kicking an allocated delegate out of their own seat. When an allocated holder remains on the seat the RPC answers `{ok: false, reason: 'reserved', released: n}` (`n` = any stale non-allocated claims it did remove, e.g. one from before the allocation existed; the client still nudges when `n > 0`). People hides the Remove button on a seat whose every holder is `reserved` and shows `stg_kick_reserved` ("This seat is reserved for its allocated delegate") instead, and shows the same text if the server refuses. Honest limits: this protects only allocated ACCOUNTS on reserved seats. An open seat, an anonymous device, or a reserved seat held by someone else can still be kicked by anyone holding the (readable) chair code, and the kicked device is locked out of that seat for 10 minutes. It is a courtesy tool, not a permission.
- `claim_delegate_seat` gained exactly one check, AFTER the seat lock (the kick takes the same lock): a tombstone for THIS seat from the last 10 minutes matching this holder key or this device hash deletes this holder's / device's own claim on that seat and answers `kicked`. It used to run before the locks, so a re-verify waiting on the seat lock while the kick committed inserted a fresh claim and then answered `kicked` forever after without removing it, leaving the seat looking taken for 65 minutes. Everything else in the function is byte-for-byte the previous body (reserved before roster, lock order, 65-minute expiry, one device per account, `p_takeover` default true). Anyone else can take the seat at once. The removed device may take a DIFFERENT open seat; that is deliberate (a delegate on the wrong seat can move).
- `/delegate/[code]`: `accessState 'kicked'` renders "You were removed from this seat by the chair" (`delegate_seat_kicked_title` / `_body`) with Back to join, from the load claim or the re-verify. The page listens on `seat-kick-<committeeId>` and re-verifies at once on a matching country, but never trusts the broadcast: only the server's `kicked` stops it. Roll call status is not changed by a kick.
- **Removed means removed (17 Sep 2026).** Three things used to leave a removed delegate half in the room, and all three are closed:
  - The re-verify held ONE check at a time behind a boolean `busy`, set before an `await` on an RPC with no timeout. A request that never settled (a phone that lost its network mid-flight) left the flag set for the life of the page, so the 30 s tick, the tab-visible check AND the chair's kick broadcast were dropped silently from then on. `busyAt` is a timestamp now (anything older than 15 s is not in flight), and `claimDelegateSeat` races its RPC against `SEAT_RPC_TIMEOUT_MS` (12 s) and answers `error`, which is the one answer nothing acts on.
  - `check()` also returned early whenever `idle.isIdle()`, which is right for a heartbeat (an idle page must stop refreshing `last_seen_at`) and wrong for a removal. `check(takeover, force)` takes a `force` flag that skips the idle guard, and the kick broadcast, `visibilitychange` and `online` all pass it. A quiet page is exactly the one a chair removes.
  - A stop screen was only a RENDER gate: the page went on holding its `startSessionSync` subscription, so every chat message, document and motion still streamed into the removed device for as long as the tab stayed open. `seatLost` (taken / kicked / elsewhere / denied / signin, never `error`) now stops the sync, and `retrySeat` bumps `loadAttempt` so "Use this device instead" and "Try again" bring the room back.
- **The kick does NOT touch the floor.** `kick_delegate_seat` only deletes seat claims: a delegation removed mid-speech keeps the floor, its running clock, its place in the GSL or caucus queue and its roll-call status (verified 17 Sep 2026: France speaking with the clock running, kicked, `current_speaker` and `speakers_list` byte-identical afterwards). That is deliberate: the seat is the DELEGATION, not the person, so a replacement claims it and picks the speech up. A chair who wants the delegation off the floor uses the strip X or the sidebar row (`handleRemoveCurrentSpeaker`), which is a separate act.
- `remove_session_chair(p_code, p_name)`, chair-gated: `array_remove` from `chair_names`, refused (`moderator`) for the gavel holder, which is `settings.headChair` or `chair_names[1]` when none is set (removing that name would move the gavel). A name no longer in `chair_names` answers `{ok: false, reason: 'not_found'}` (People shows `stg_chair_remove_not_found`, "That chair is no longer on the dais"); it used to answer `ok: true, removed: false` and People reported success. `release_chair_device_claim(p_code, p_key)` forgets one signed-in chair account's device claim. Neither locks anyone out: the chair password is still the only credential.
- Moderator only in the UI (`!isViewOnly`), every removal behind a `ConfirmSheet`. Commenters see the tab read only. Since 17 Sep 2026 the People tab exposes ONLY the seat kick: `removeSessionChair` / `releaseChairDeviceClaim` (and the RPCs) still exist in `src/lib/sessionParticipants.ts` but no UI calls them. NOT a security boundary (rule 15): the suffix is anon-readable.

There is **no** custom-session-ID control, **no** multi-chair toggle and **no** delegation-name-requirement setting. `updateCommitteeCode` (`committeeService.ts:937`) and `migrateSettings` (`settingsStore.ts:179`) are both dead code — nothing calls them. `requireDelegationName` has zero occurrences in `src/`.

### `scoring` sub-object (`ScoringConfig`, defaults in `settingsStore.ts:34-53`)
Persisted into `settings.scoring`; read everywhere via `getScoringConfig(committee)` — never via localStorage.
- `sources` — `ScoreSource[]` (id, name, value, enabled, builtin). Ten built-ins (attendance, gslSpeech, caucusSpeech, speakingTimePer10s, motionRaised, motionPassed, rightOfReply, wpSponsor, drSponsor, drPassed); chairs can edit values and disable any. **A stored `sources` list REPLACES the defaults**, so a built-in added later (motionPassed, 18 Sep 2026) is appended at READ time by `withBuiltinSources` / `withBuiltinScoring` (`settingsStore.ts`), used by `getScoringConfig`, the store's `getSettings` and `hydrateSettings`: no backfill, nothing stored is reordered, and Settings lists it through the ordinary sources list (the first save writes it). A motion ledger row carries `motion` (the event's fields); its `detail` is `describeMotion(..., 'en')` for the organiser board and is re-described in the reader's language by `buildSessionScoreboardRows`. Creating a custom source was removed from Settings (16 Sep 2026); custom sources already stored still render and still score. Disabled → the ledger row is omitted entirely.
- `factors` — `RankingFactor[]`, the subjective per-speech qualities chairs rate (Diplomacy, Public Speaking, Collaboration, Content & Research by default).
- **`level` is `'speech'`, with ONE exception.** `FeedbackLogPanel` writes only that level; the document sponsor notes write `'document'` (`src/lib/documentNotes.ts`, see FEATURE: DOCUMENTS), which no speech reader picks up; nothing anywhere writes `'session'` or `'conference'`. The delegate's own recap filtered on exactly those two levels, so it was permanently blank — a delegate could be rated all session and see nothing. It now falls back to the mean of the per-speech ratings, the same fallback `computeQualityScore` already used, and says so on screen. If you ever add a real end-of-session recap, write one of the other two levels and both surfaces pick it up automatically.
- **`parseLogEvents` is memoised on `committee.messages` array identity** (`scoring.ts`). Every per-delegate fold parses the whole log, so a scoreboard over D delegates ran D full passes and D x M `JSON.parse` calls — and it got worse the longer a committee ran. Safe because the array is replaced, never mutated: `mergeMessagesById` returns `prev` only when nothing changed, and a new array otherwise. NEVER start mutating `committee.messages` in place.
- **Built-in factor and source names are localized through `src/lib/scoringNames.ts`** (`factorName` / `sourceName`), on exactly the `motionNames()` contract: a stored name that is empty or still the canonical English default means "never renamed", so the localized default wins; anything else is a genuine rename and shows verbatim in every locale. `DEFAULT_FACTOR_NAMES` / `DEFAULT_SOURCE_NAMES` must stay BYTE-IDENTICAL to `DEFAULT_SCORING` in settingsStore.ts — if they drift, rename detection silently breaks and every committee looks renamed. Applied on the session surfaces only (`buildSessionScoreboardRows` takes a `language`); the organiser board is English by design.
- `factorRatingsEnabled` — **default false**. Gates the per-speech rating sliders in the feedback dock. It gates the INPUT ONLY: ratings already recorded always render on the scoreboard, so turning it off can never hide data. Off by default because in the entire history of the product only a couple of ratings were ever set deliberately, and `scoreBlend` defaults to 0 so they moved no score anyway.
- `factorScaleMax` — upper bound of the factor rating scale (**default 10**; was 100). Committees that already held a real rating had `factorScaleMax: 100` pinned into their settings by a backfill, so the default change cannot reinterpret existing data. The Settings slider floor is 2 — a one-point scale is not a rating.
- `scoreBlend` — 0 = pure objective points … 100 = pure subjective quality. Consumed by `computeHeadline`.
- **The session scoreboard and the organiser scoreboard are ONE component**: `src/components/ScoreboardTable.tsx` (moved out of `manage/[slug]/live/`, which now re-exports its palette from `src/components/scoreboardTokens.ts` so all conferences-side importers resolve unchanged). `ScoreboardPanel` feeds it via `buildSessionScoreboardRows` (`src/lib/sessionScoreboard.ts`), a pure adapter from a live `Committee` to `ScoreboardDelegateRow[]` that reuses `scoring.ts` — no scoring maths is duplicated. Every session-specific capability is a defaulted-off prop (`locale`, `detailSummary`, `detailExtra`, `Stat.title`, and since 16 Sep 2026 `onSortChange` + `sortDir`, `circleFlags` + `flagSize`, `renderDetail`, and `sortScoreboardRows`'s optional `dir`); **Since 23 Sep 2026 the organiser side passes them too, on purpose** (owner: "the scoreboard ... should be the absolute same"): see "The organiser side renders the chair's scoreboard" below. `DelegateDetail` and `CommitteeScoreboardBody` are no longer rendered by any organiser surface.
- **The chair's scoreboard (16 Sep 2026, simplified 17 Sep 2026)** has no SORT BY control: the column headers sort (press again to reverse; the button sits in a `role="columnheader"` cell carrying `aria-sort`, the header strip is `role="row"`). Rows draw `SeatCircleFlag` at 34px (26px in the Matrix). The session figures above the tabs are three icon chips (delegations, speeches, speaking time). **No chair-note counts anywhere** (owner): no notes chip, no NOTES column (`hideNotesColumn`), no note count in a profile or a History header. Session-only table props added 17 Sep 2026, all defaulted off and passed by no organiser caller (verified again: HEAD and new `ScoreboardTable` render byte-identical organiser markup, collapsed, expanded, with and without the committee column, `DelegateDetail` and `CommitteeScoreboardBody`): `hideNotesColumn`, `columnWidths` (the chair passes 92 / 84 / 96 so translated headers fit), `wrapHeaders` (labels wrap instead of an ellipsis; measured unclipped in en, es, ar), `renderScore` (the chair's score cell: the headline in 16px tabular forest numerals with a small `sb_pts` unit, over a 52px bar relative to the top score, gold for the leader; the blended/objective explanation stays in its tooltip).
- **Opening a delegation** renders `src/components/scoreboard/DelegateProfile.tsx` through `renderDetail`, never `DelegateDetail`. Compact, top to bottom: ONE line (flag, name, speeches, speaking time, rank `#n` with `sb_profile_rank_title`, the headline pill); ONE stacked bar of where the objective points came from with a legend of source name and value (`sessionPointSlices` in `sessionScoreboard.ts`: the row's ledger folded by source, time bonus banked to `speakingTimePer10s`, every manual row one `manual` slice labelled `sb_breakdown_manual`, sums to `row.objective`; negative slices are legend-only, in red); RATINGS one line per factor (dots for a scale up to 10, else a small bar, then `avg/max`), and the section is not rendered at all when no rating exists; the TIMELINE, newest first: every speech of the delegation from the History model (context label `sb_hist_seg_*`, duration, time, points) with the chair comments written on it inline, plus the other timestamped ledger rows (motion, RTR, documents, manual), then `sb_profile_other_comments` for notes that match no speech. No topic is printed on any row. Speech points are found by `speechKey(country, timestamp, context, seconds)` (`sessionHistory.ts`), which a ledger speech row and a History speech share because both come from `parseLedgerEvents`. The manual control is `scoreboard/ManualAdjust.tsx` (the profile's `extra`, keyed by row): minus, the pending change, plus, then an optional reason and Apply. **Every chair adjusts points, Moderator and Commenter alike (Oct 2026)**: `ScoreboardPanel` passes it whenever the session has not ended (`applyManual` also returns on `endedAt`; its `isViewOnly` prop is no longer read), and the organiser board never passes it. It writes one `logEvent` of `manual-award` / `manual-deduct` with the absolute value, and the row also names the chair as an extra `by` field in its JSON (when there is a `?chairName=`); every other ledger reader ignores it. `manualAuthorIndex(committee)` (`sessionScoreboard.ts`, keyed by `manualAuthorKey(country, timestamp, type)`) feeds the profile and History, which read "Points awarded by Aida" (`sb_adjust_by`, `{action} by {name}`); rows from before, or with no author, read as before. The reason is optional (a bare award shows "Points awarded" in the timeline). A speech logged with context `unmoderated-caucus` is labelled with the committee's consultation name (`consultationName` = `motionNames(...).consultation`), since only a Consultation floor holder logs it.
- **History segments follow the room, not only the speeches (18 Sep 2026).** ROOT CAUSE of "after moving into an unmoderated caucus, History still shows it under the General Speakers' List": segments were derived ONLY from speech contexts and the log recorded no phase change, so a caucus with no logged speech (every unmoderated caucus) never opened a segment and the motion and everything after it stayed in the preceding GSL segment until the next GSL speech. Now: a `motion-passed` of a caucus type OPENS a segment (`moderated-caucus`, `unmoderated-caucus`, `consultation` (new kind, header = the committee's motion name), `tour-de-table`) that takes that caucus's speech contexts (since Oct 2026 a speech with context `unmoderated-caucus` itself opens a `consultation` segment, not an unmoderated one: only a Consultation floor holder logs that context) until a speech of another context or the next opener; ties at the same millisecond sort speech, then other events, then the pass (`TIE_RANK`), because the speech a caucus interrupts is stamped in the same ms. And `liveSegment(committee)` appends an empty `live: true` segment for the debate the room is in when the newest segment is a different kind (a caucus accepted by an older client, or the GSL a caucus returned to before its first speech). Honest limit: nothing logs "the caucus ended", so an event between the end of a caucus and the first GSL speech (a right of reply, a manual award) is filed in the caucus segment.
- **Every motion raised is a line in History (18 Sep 2026)**: an indented `motion` event in the segment it was raised in, the proposer's 20px round flag (a gavel disc for `__chair__`), the description from `describeMotion` ("Moderated Caucus 10:00 / 1:00 · topic", in the committee's own motion names), and its outcome as an icon + plain word (`sb_hist_motion_passed` / `_rejected` / `_failed` / `_fell` / `_pending`; no status pill). Pass / fail / edit events update that one line; an outcome with no raise line (raised before this shipped) draws its own. A line still `pending` whose id is no longer in `committee.pendingMotions` shows no outcome. Rights of reply carry the dock's notes on them (`HistoryEvent.notes`, `attachReplyNotes`), and a note stored under context `right-of-reply` is never attached to a speech.
- **History** (`scoreboard/HistoryTab.tsx`, model `src/lib/sessionHistory.ts`) reads the session back newest first: a run of logged speeches sharing `context` + `topic` is one segment, non-speech log events sit in the segment running when they happened. The header is only the kind (`sb_hist_seg_gsl` = "General Speakers' List", "Moderated caucus", ...), its start to end time and the total speaking time; the caucus purpose is its tooltip only. A speech row is round flag, delegation, time, duration, and the chair comments on it inline with their author; no context label and no topic. Event rows use the same columns. Notes match on country + context + seconds, resolved to the nearest speech in time and consumed once per author; a note with no seconds (written mid-speech) attaches to the same delegation's nearest speech within 10 minutes, otherwise it is left out of History (the profile still lists it under Other comments). **Document notes never reach History (Oct 2026):** a `feedback` row whose `speech_context` starts with `doc` (`isDocumentNote`, `sessionScoreboard.ts`; the sponsor notes of FEATURE: DOCUMENTS) is filtered out in `buildSessionHistory` and by `ScoreboardPanel` before History is built, so it is never attached to a speech of its sponsor; it stays in the profile's Other comments. A `yield` event reads `sb_hist_yield` ("yielded 0:42 to Brazil", `HistoryEvent.to` / `seconds`). **Newest first throughout (17 Sep 2026, owner: "the most recent at the top"): the segments, and the rows INSIDE each segment.** The rows were the one place still reading oldest-first, so the caucus a chair had just left put its last speech at the bottom; the sort in `HistoryTab` is now descending, like the profile timeline, which always was. Newest segment open by default, others closed, several may be open. `ScoreboardPanel` builds the same History once more for the profiles, so both surfaces place a note identically. Chair-private: only `ScoreboardPanel` mounts these, and only the chair page and the chair-gated voting page mount that. Pure fold of `parseLedgerEvents` + the loaded `feedback`; no I/O, no scoring maths.
- **Chair comments are edited where they are read (17 Sep 2026, owner: "make the previously written comments in the scoreboard and history editable by simply clicking in").** In the History tab AND in a delegation's profile timeline (including its "Other comments"), a comment is `src/components/scoreboard/EditableNote.tsx`: a click (or Enter / Space on the focused note) turns the text into a textarea, Enter or blur saves, Escape cancels, Shift+Enter breaks the line. An EMPTY box is a cancel, never a write: clearing a note would leave a row rendering as nothing that could never be reopened.
  - **Only the author's own rows.** A `feedback` row belongs to the chair whose `chair_name` is on it (the same rule the comment dock claims rows by). Another chair's note renders exactly as before and says whose it is on hover (`sb_note_readonly`). The rule is in three places on purpose: the UI, the panel's `saveNote`, and the statement itself, which is `.eq('chair_name', chairName)` — because `isViewOnly` and hidden controls are never a permission (rule 15) and every chair device holds the suffix.
  - **Moderator and Commenter both**, since both are chairs; the editor never reads `isViewOnly` (that still gates only `ManualAdjust`). The identity is the panel's new `chairName` prop, passed by `/chair/[code]` (`myChairName`) and `/voting/[code]` (`urlChairName`); with no `?chairName=` nothing is editable.
  - **The write is `updateFeedbackContent` (`src/lib/feedbackEdit.ts`), NOT `updateFeedback`.** The dock's writer returns void, and supabase-js resolves with `error: null` both for an RLS refusal and for a zero-row update (RULE 5), so this one asks for `.select('id')` and counts the rows. Content only; ratings stay in the dock.
  - **Optimistic, then rolled back.** `ScoreboardPanel.saveNote` patches its `feedback` array first, so the History tab and the profile change together (they read the same rows), then awaits the checked write. A write that did not land puts the old text back and leaves the editor open with what the chair typed plus `sb_note_save_failed`, so nothing typed is lost. The realtime `feedback` echo bumps `feedbackVersion` and the panel refetches as usual; the comment dock picks the new text up the same way.
  - The panel passes this down through `NoteEditingProvider` (a context with no DOM node of its own, so the dialog's flex column is unchanged). Keys: `sb_note_edit_hint`, `sb_note_edit_label`, `sb_note_readonly`, `sb_note_save_failed` (all four locales).
- The row badge is the BLENDED headline; the ledger below it sums to the OBJECTIVE total. These legitimately differ whenever `scoreBlend > 0` — label them, never print one number in both places.
