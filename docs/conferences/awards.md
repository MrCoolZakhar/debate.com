## 5. Awards (SET-UP, REVIEW AND PUBLISH LIVE IN SETTINGS, 12 Oct 2026)

**Current state, read this first.** Owner, 11 Oct 2026: "set up the awards just for now. Make it simple, just like starting from a blank slate ... If a conference does not set up awards, never offer it to chairs."

- **Manage → Settings → Awards** renders `settings/awardsUi.tsx` (`AwardsSettings`; the coming-soon screen `awardsComingSoon.tsx` was deleted). Three screens, one next step each: (1) **blank slate**, "No awards yet" + **Set up awards**; (2) **one question**, "Will every committee give the same awards?": "Yes, the same for all" (Recommended) or "No, set them per committee", with "You can change this later and give any committee its own awards"; (3) **the editor**: a "Same awards for every committee" switch and, when off, a committee picker ("All committees" = the shared set, then each committee, acronym over full name, marked **Same as all** or **Own awards**; a committee with no own set offers "Give it its own awards", which copies the shared set; "Use the shared awards again" drops it). Then the award cards in three groups: **Placements** (Best Delegate, first place, with a "Diplomacy Award" name option; Outstanding Delegate, second; Honourable Mention, third), **Other awards** (Most Improved, Verbal Commendation, Best Position Paper), **Custom awards** (typed name; its icon is `TrophyQuestion`, the 3D Trophy with a gold "?" badge). Each card is a switch; an award that is on shows a name chooser / rename field (the key never changes) and a "Per committee" stepper (1..10; Honourable Mention starts at 2). Autosaved (600 ms, row-counted through `saveAwardsConfig`, flushed on unmount; failures as a glass `notifyErr`). "Turn off awards" (confirmed inline) sets `setUp: false`; setting up again restores the earlier choices.
- **Config shape** (`src/lib/awards.ts`, `conferences.awards_config` jsonb, extended, never renamed): the old `types` / `requireApproval` / `chairDeadline` / `configuredAt` / `enabled`, plus `setUp: true` (written when the question is answered), `sameForAll` (default true) and `perCommittee: { [conference_committee_id]: { types } }` (read only while `sameForAll` is false; kept when switching back). A committee's own `types` REPLACES the shared list for that committee. `getAwardsConfig` returns `enabled = stored enabled AND setUp`, so **`{}` reads as NOT set up**; the eight configs the old screen saved on purpose (`configuredAt` plus `types`: SISMUN, GAMUN, AMUN Global II, KU MUN, VelorumMUN, UGMUN (switched off), LIMUN, Velorum) count as set up, one shared set, so their chairs keep their awards. New key: `most-improved` (never suggested by `suggestSlate`); custom keys stay `custom-<slug>`. Helpers: `configForCommittee(config, ccId)`, `committeeHasOwnAwards`, `awardsOfferedFor(config, ccId)` (set up AND at least one slot for that committee), `AWARD_PRESET_GROUPS`, `freshAwardTypes()` (the three placements on). `slateState` now answers `published` before `off`.
- **Chairs are offered awards only through `awardsOfferedFor`.** Gated: the chair's `AwardsCard` (renders nothing unless offered or already published; uses `configForCommittee`, so a chair sees their own committee's set), and every session signpost through `useChairAwards(code, isConference)` / `resolveChairAwards(code)` in `src/lib/sessionAwardsLink.ts` (anon read of `conference_committees.session_code` → `conferences(slug, awards_config)`, cached 5 min, a failed read = not offered): the ScoreboardPanel header link, the End View card and the top-bar CTA on `/chair/[code]` (`ChairAwardsCta` returns null), and the session Settings → Awards tab (`SettingsPanel`). The organiser Live recap (`LiveModals` `AwardsRecap`) also reads the per-committee set. Published awards (`MyAwardsCard`, `/account/cv`, the honour roll) are read by status and never pass through the gate.
- **Database: unchanged.** Checked 11 Oct 2026: no function, constraint or policy reads award_type keys or the new fields (`publish_conference_awards` reads only `requireApproval`). The gate is UI-only today; `scratch-awards-setup.sql` is an UNAPPLIED, untested draft that adds it to the chair INSERT policy and `submit_committee_awards`. 28 nominated rows (0 published) exist from before; they are untouched.
- **The tab's layout (13 Oct 2026; organisers missed Review and Publish under the editor):** once set up, two columns from 960px of section width, one column on a phone with Review and Publish FIRST. Left: **Conference Awards** (a read-only list of the awards being given: name on the certificate, Placement or Other, "N per committee", and for a custom award the committees that give it when not all) with **Edit awards** opening a pop-up (`settings/awardsSheet.tsx`, the Settings pop-up shell) with Placements and Other awards (the same switch, name chooser, "Name on the certificate" and "Per committee" controls) and **Custom award**, which turns the same pop-up (back arrow) into a short form: "Name on the award", "Amount per committee" (1 to 10), "Which committees get it" (All committees, or picked committees); existing custom awards are edited and removed from the same list. Then **Awards per Committee**: one switch, "Same awards for every committee" (`sameForAll`); turning it off opens a pop-up of every committee ("Same as all" or its own list), a committee opens "{SHORT}'s Awards" (switch each award, change its amount; changing anything gives it its own set; "Use the conference awards again"), with "New awards are added in Conference Awards" linking to Edit awards. While off, the card lists committees with their own awards and a Change link; turning it back on asks first and reverts them all. "Turn off awards" stays at the foot of the left column. Right: Review and Publish (below).
- **Committee-only custom awards (13 Oct 2026):** an optional `committees` list (conference_committee ids) on the award type inside `awards_config` (no database change); absent or empty means every committee. `configForCommittee` drops an award for any committee not listed, in the shared set and in a committee's own set, so `awardsOfferedFor`, the chair's AwardsCard and every reader that goes through it never offer it there. Keys stay `custom-<slug>`, fixed when the award is made. The conference awards are the catalogue: adding, removing or renaming an award there, or changing its committees, is carried into every committee's own set (`syncOwnSets` in `awardsUi.tsx`); what a committee switched on and how many it gives stay its own.
- **Slates waiting for you (13 Oct 2026):** committees with `awards_submitted_at` set, `awards_approved_at` not set and awards not all published (`awardsWaitingCount` in `src/lib/awards.ts`, read by `loadAwardsWaiting` in `src/lib/awardsWaiting.ts`) count on the manage sidebar's Settings badge (added to the role set-up problems), on the Settings tab strip's Awards tab, and as "Waiting for you" on each submitted committee row. Approve, Return and Publish fire `gv-settings-flags-changed`, so every badge re-reads at once.
- **Review and publish (12 Oct 2026)** is the right column of Settings → Awards (13 Oct 2026; a press on a committee opens its slate in a pop-up instead of an accordion), only once awards are set up: `settings/awardsReview.tsx` (`AwardsReview` loads and writes, `AwardsReviewView` is the pure view), mounted at the end of `AwardsSettings`. A **Review and Publish** card lists every committee (round logo, acronym over full name, filled against that committee's set from `slateCompleteness(rows, configForCommittee(...))`, the state as a 3D emoji plus words: Not started, Nominating, Submitted, Returned, Approved, Published). The state is per committee (`reviewState`: published when it has awards and all are published, else its own stamps), because `slateState` answers Published for every committee once the conference published at all, which would hide a late slate. Submitted committees come first with a gold edge. Opening one shows each nominee (award name from the committee's set, round flag or initials, live name over country) with **Approve** (`approveSlate`; "Approve as it is" for a slate the chairs never submitted) and **Return with a note** (`returnSlate`, note required, the chairs read it; also offered on an approved slate to unlock it). A **Publish Awards** card publishes the whole conference (`publishAwards`) after a `ConfirmModal` ("Publish awards for N committees? Winners see them on their MUN CV and the public honour roll. This can't be undone."); with `requireApproval` (the default) only approved slates go, and it says how many committees are not approved and wait. Afterwards it reads Awards Published with the count, the date and a link to `/conferences/[slug]/awards`, and "Publish new awards" appears whenever later approved rows exist (the RPC only touches unpublished rows). **Publishing sends no email**: none of the three RPCs nor any trigger on `conference_awards` / `mun_cv_entries` queues one, and this screen does not call `queueAwardReceivedEmails` (the retired desk did); whether winners get an email is the owner's call. The retired desk `AwardsConsole.tsx` stays unrendered (edit slate, delegation awards and certificates CSV are not rebuilt).
- Awards is still not a dashboard checklist item or a verification criterion (removed 7 Sep 2026: `conference_setup_status()` setup_total 9 → 8, `SETUP_STEPS`, the nudge emails).

Model UN awards are given once per conference, at the closing ceremony. Per committee the dais names a Best Delegate, usually one or two Outstanding Delegates, a few Honourable Mentions, sometimes Verbal Commendations and a Best Position Paper. The secretariat sets categories and quotas beforehand, collects each committee's slate, ratifies it and announces. Delegation awards go to a school or society, tallied from committee honours.

Gavelling mirrors that exactly. Read `src/lib/awards.ts` (the vocabulary and config) and `src/lib/awardsService.ts` (every read and write) first.

Rules:
- **Awards only on conference-linked sessions.** The live session signposts (`ScoreboardPanel` header, the End View card) only when `committee.sessionOrigin === 'conference'`. No award UI in anonymous sessions, ever.
- `award_type` keys are stable identifiers; labels are presentation. `DEFAULT_AWARD_TYPES` point values are unused: points are retired and `award_points_for()` no longer exists.
- Nothing about a nomination is visible to a delegate before `publish`. Do not add a read path that bypasses the `conference_awards` RLS.
- The chair's decision is qualitative; the scoreboard is evidence. "Suggest from the record" fills empty slots and is always editable.
- `CONFERENCES_PRD.md` rule 11 ("ratings and award badges are not in scope") is about badges on directory cards, not this feature; Part 7 of the same PRD mandates it.
