## 7. Sessions runtime in one screen

- `Committee.speakersList` is the General Speakers List: permanent, never touched by a caucus. `caucusQueue` is temporary and wiped when the caucus ends. `currentSpeaker` is its own row and is never in either list.
- `SessionPhase`: `pre-session → roll-call → speakers-list → moderated-caucus | unmoderated-caucus → voting → adjourned`. `CaucusState` is a JSONB column on `committees`.
- Motions sort by `disruptiveness`, configurable per committee via `motionOrder`; end/suspend debate always outrank caucuses; custom motions sort last.
- Optimistic writes: `updateLocal()` first, DB write fire-and-forget. Incoming realtime echoes are ignored for **3 s** after a structural local write (`localUpdateTime`), with carve-outs for broadcasts, chat, feedback and the view-only Commenter, who never debounces.
- Timers are **clock-anchored**: persist `started_at` + duration once, every client derives the remaining time locally. There is no per-second write and there must never be one.
- `speakers_list.position` reorders happen in place (parallel `position` updates), never delete-and-reinsert, because a DELETE event flashes an empty list on delegate phones.
- Tables: `committees`, `delegates`, `speakers_list` (`list_type` gsl | caucus), `current_speaker`, `motions`, `documents`, `messages` (chat + the `__system__`/`__log__` scoring ledger), `feedback`, `session_broadcasts`.
- **Agenda (conference rooms with 2 or 3 topics).** Before roll call the Moderator picks the topic with big 1/2/3 numerals (`src/components/AgendaPicker.tsx`); it writes `committees.topic` and `settings.agendaTopicIndex`. Presence of the index means "chosen". The organiser editor's re-sync keeps the room's current topic text when it still exists. Single-topic and standalone rooms are unchanged.
- **Speakers (Oct 2026).** Settings → Access → Speaker clock (`autoStartSpeakerTimer`, default off) makes Next seat the next speaker with the clock already running, in the same single current_speaker write. **Yield** (GSL, `src/components/YieldPopover.tsx`) gives the speaker's remaining time to the next speaker (added to their slot) or to another delegation (timed locally like Right of Reply), and logs one `yield` ledger row that scores nothing. In a moderated caucus the caucus speaker keeps any GSL place (`gslDedupeApplies`). A Consultation of the Whole floor holder is set by the Moderator only and credited with the caucus clock time that ran, never wall time.
- **Chat: a new conversation stays open (prompt 116, 12 Oct 2026).** The owner's "a new chat closes after one letter" (room RAAGKK, 10 Oct) was the delegate Sheet pulling focus onto itself on every re-render of the page: in a busy room each realtime event re-rendered it, so after one key the box lost focus (the phone keyboard dropped and the sheet jumped) and the next keys went nowhere. Reproduced on the code before Peter's fix (2310af24) and no longer on this branch, in a plain room and in one where a chair shares a seat's name. Since then the open conversation, the one-pane thread flag and the unsent text live in `src/lib/chatOpenConversation.ts` (keyed by committee and reader), so a re-render or remount keeps them; they are dropped when another conversation is picked, on Back, and when Chat closes (which opens on the list next time). A key missing from the list for a render keeps its conversation open instead of falling back to Everyone. The one-pane / two-pane switch flips only at 660 (to two) and under 620 (to one), so a scrollbar or keyboard near 640 cannot move it. `npm run test:e2e` (`e2e/chat-new-conversation.spec.ts`, Playwright, against a running server) types a sentence into a new conversation in a busy room at phone, tablet and laptop sizes.
- **Absent delegations stay off the lists (13 Oct 2026, owner).** An Absent delegation cannot be added to the speakers list or a caucus queue from any entry point (a sidebar row, a keyboard press, the search bars, Add first or Add last), and its attendance never changes there; the chair sees "This delegation is Absent" (top right, `src/lib/absentNotice.ts`) and must use Roll Call, whose slider now also answers that delegation's waiting-room request. Details in AGENTS.md.
- **Voting opens on the roll call (13 Oct 2026).** Entering voting renders the roll call first, with no flash of the paper list or the ballot and no fade-in lag.
- **Moving through the line (13 Oct 2026).** On the ballot the chair can move back and forward through countries that already voted (flags, the Previous / Next arrows and the arrow keys), never past the first one that has not voted. Details in AGENTS.md.
- **Comment dock and papers (Oct 2026).** The Commenter dock (`FeedbackLogPanel.tsx` + `src/lib/commentDockSync.ts`) has one writer per note (`NoteSync`: one write in flight, client-chosen row ids, localStorage drafts), never moves a chair off a note being written, and re-reads other chairs' notes on every `feedback` event and every 15 s. A Commenter can also take notes on each sponsor of a paper (Take notes, `SponsorNotesView`, `feedback.level = 'document'`) and adjust points on the scoreboard (the ledger row names the chair). The Moderator can add time to a document introduction stage (`StageAddTime`). Roll call, placards, list removals, topic, agenda and settings patches park offline and survive a reload (`src/lib/pendingRollCall.ts`). Every motion is drawn by one card (`src/components/motions/MotionCard.tsx`) with the proposer's round flag. Details in AGENTS.md.
- **Gavel knock.** `gavelSoundEnabled` / `gavelSoundAtSeconds` (default on, 15 s). A synthesised double knock (`src/lib/gavelSound.ts`, no audio file) plays once when a running countdown crosses the mark, on the Moderator's laptop only. `useGavelCue` is a read-only side effect of the timer values: rules 3 and 4 still hold.
- **End Debate is reversible for 24 hours (7 Oct 2026, owner: committees were ended by accident).** `endDebate` keeps the room `ENDED_KEEP_HOURS` (24 h, `src/lib/roomRetention.ts`, was 1 h, which deleted an accidentally ended standalone room before anyone could get back to it), and `reopenEndedSession` (`committeeService.ts`) lifts the end in ONE conditional statement and lands the room in `pre-session`, where a resumed suspension lands, so it can never come back with a running clock. The window is checked against the database clock and offered to any chair on the End View, not only the Moderator (the join page sends every chair to an ended room as a Commenter). A CONFERENCE room is never auto-deleted at all (`delete_expired_committees()` filters `session_origin <> 'conference'`), so it always outlives the conference. Rules in AGENTS.md, FEATURE: END DEBATE.
- **Seats.** Conference rooms gate per seat: a seat with an allocation or invite is reserved for that person, every other seat is open to anyone with the code, and chairs use the chair password when nobody was invited to chair. **Chair password (13 Oct 2026):** it is shown and typed as the 4 digits of `chairJoinSuffix` alone, called "chair password" everywhere people see it: the organiser's chip on the committees page ("CHAIR PASSWORD", copies only the digits, with an Info hint, shown only while the dais is open) and the join page's "Chair password" field; typing the old full form (CODE-1234) as the session code still fills it in. **Join fix (same day, Omni MUNC'26 HY62XX):** in a room nobody has chaired yet the join page shows only the new-name field, and the Join button now reads that field too (a derived name mode), so it turns on; a conference room with no countries says "Delegates can join once the organizers add countries to this committee" under JOIN AS, and the committees page says "No countries yet" ("No roles yet", "No members yet") instead of "1 seat". One person per seat through `delegate_seat_claims` and its RPCs. This stops honest collisions, not a hostile user: session writes still check only the session code. Details and limits in AGENTS.md.

Everything else, with line numbers and the reasons behind each rule, is in `AGENTS.md`.
