## 1. What Gavelling is

Two products in one Next.js codebase, sharing one Supabase project (`luruhkwrgisytejswlas`):

| Product | Identity | Money | Who |
|---|---|---|---|
| **Sessions** | anonymous, 6-char code (+ 4-digit chair suffix) | free, forever | a chair running a committee room from a laptop; delegates following on phones |
| **Conferences** | Supabase Auth accounts | organiser pays nothing; participants pay | secretariats managing hundreds of applications, allocations, papers, payments and awards |

The two meet at the database: a conference committee mints a live session (`committees.session_origin = 'conference'`, linked by `conference_committees.session_id`), and the secretariat watches every room from `/manage/[slug]/live`, reads the cross-committee scoreboard, and turns the record into awards and verified MUN CV entries.

**A live room is only ever created by a press (owner, 7 Oct 2026: "committees should only be started when chairs want it to").** `mintConferenceSession` (`src/components/CommitteeEditorModal.tsx`) is the one minting primitive, and `mintSessionForCommittee` (`src/lib/mintSessionForCommittee.ts`) is the one shared wrapper that seats a room from `committee_country_slots`. It has exactly three callers, all presses: saving a brand new committee in the editor, the organiser's "Create session code" button (per committee, plus one "Create codes for N committees" on `/manage/[slug]/committees`), and "Start your committee room" on the chair's own role page (`conferences/[slug]/participant/ChairParticipant.tsx`). **Never mint from an effect, a page load, a publish or a cron.** The committees page used to mint every codeless committee on arrival, in a loop: 13 rooms in a minute for one conference and 735 rooms across production that nobody ever used. The known cost of this rule is that `queue_chair_session_reminders` (cron `chair-session-reminders`) selects `where cc.session_code is not null`, so a committee nobody started gets no chair reminder email, and that is now the organiser's or the chair's decision rather than ours.

**A chair starts their own room through an RPC (7 Oct 2026).** A mint's last write is `update conference_committees set session_id, session_code`, and that table's only non-SELECT policy is `Organizers manage committees USING is_conference_organizer(conference_id)`; `chair_user_ids` grants SELECT only, and a zero-row UPDATE is reported as success, so a chair minting from the browser would get a working join code for a room nothing on the conference side points at (an orphan from birth, the class of the 109 orphans already in production). So the chair's "Start your committee room" button calls `start_my_chair_session(p_committee)` (SECURITY DEFINER, `search_path = public, pg_temp`, EXECUTE for `authenticated` only, anon revoked): it allows an assigned chair of that committee or the organising team, takes the committee's own advisory lock, and does the same four writes as `mintConferenceSession` in ONE transaction, so a room can never exist unlinked and two chairs pressing together get one room. Idempotent: a second press returns the existing code. Refusals carry a plain `message` the chair reads as written (`signed_out`, `not_found`, `denied`, `no_code`). There is no organiser gate on the button any more. Verified in a rolled-back transaction on apply: a stranger `denied`, the chair created a 40-seat room linked to its committee, a second press returned the same code. The organiser's own buttons still use the four client writes through `mintSessionForCommittee`; if the shape of a minted room changes, change both.

**The strategic position** (`CONFERENCES_PRD.md`, `docs/competitive-mymun.md`): the incumbent directory charges organisers per participant per day; Gavelling charges the organiser nothing, is merchant-of-record through the organiser's own Stripe Connect account, and monetises the participant side transparently. Sessions is the top of the funnel and must stay free, anonymous and account-free.
